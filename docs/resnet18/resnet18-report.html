Does a forgotten network relearn faster?

A network learns CIFAR-10, then "forgets" it by training on house-number digits. We test whether the forgotten knowledge is really gone, or still hidden in the weights and quick to come back.

Runs finished 2 Nov 2026Lab GPU: RTX PRO 6000 BlackwellPyTorch 2.15.0All numbers: mean of seeds 1–3, CIFAR-10 test set unless markedOne-page summary · vs ViT

The answer in one paragraph

Yes, largely. After SVHN training, A's old CIFAR-10 classifier dropped from 94.9% to 18.8%, so A looked forgotten. But when all three networks relearned CIFAR-10 from the same 5,000 images, the one that had learned CIFAR-10 before (A) ended 7.2 points above a network that had learned a different photo dataset (C), and 16.7 points above one that had learned nothing (B). That held in every seed. About 3 of those 7 points were already visible before relearning started. The other ~4 came from A improving faster during relearning. A did not measurably remember the specific photos it had trained on: what survives is general skill with CIFAR-10, not memory of examples.

01The question

In plain words

When you learn something, stop using it, and learn something else, it feels forgotten. But relearning it later is usually much quicker than learning it the first time. We ask whether a neural network behaves the same way.

Neural networks trained on one task and then on another lose accuracy on the first task. This is called catastrophic forgetting. It is normally measured with the network's original output layer, which is a narrow view: that layer can stop working simply because the layers below it changed, even if the information is still there.

This experiment asks a stricter question: after a network appears to have forgotten a task, does it relearn that task faster and better than an equally trained network that never learned it? If yes, the "forgotten" knowledge was hidden, not erased.

What would count as an answer

  • Hidden: A relearns CIFAR-10 better than C (equal training, different first dataset), consistently across seeds, by more than the seed-to-seed noise.
  • Erased: A relearns no better than C.
  • A side question: if A is better, is it because A remembers the specific photos it trained on, or the task in general? Section 6 explains how the two relearning subsets test this.

Why it matters: real models are updated over time. If forgotten knowledge is cheap to recover, forgetting scores based on the old output layer overstate the damage, and a short refresher could restore old skills.

02Design: three arms, three stages

In plain words

Three copies of the same network take different paths. A learns CIFAR-10, B learns nothing, C learns CIFAR-100. Then all three learn house numbers, which overwrites what they knew. Finally, all three learn CIFAR-10 from a small set of photos, and we watch who learns fastest.

Why each arm exists

ArmRoleWhat comparing to it tells us
AThe test subject: learned CIFAR-10, then had it overwritten.Its relearning is what we are measuring.
CThe clean control: same amount of training as A, same kind of images, but a different label set (CIFAR-100).A vs C isolates knowledge specific to CIFAR-10. Any general benefit of "having trained on photos" is present in both.
BThe baseline: no stage 1, only SVHN.A vs B mixes two things: CIFAR-10 knowledge and simply having had more training. C vs B measures the general benefit of photo pretraining.
In plain words

Comparing A to B alone would be unfair, because B has had less training. C is there to answer: "is A better because it learned CIFAR-10 specifically, or just because it practised on photos?"

Choices in the design, and why

ChoiceWhy
SVHN as the overwriting taskA different domain (street-number digits, not objects), but the same image size (32×32) and the same number of classes (10). It trains quickly and pulls the features far from CIFAR-10.
CIFAR-100 for CSame image size, style and source as CIFAR-10, with different labels. That makes it the closest "same effort, different knowledge" control.
Relearning from only 5,000 imagesLeftover knowledge should matter most when data is scarce. With all 50k images, every arm would do well and the gap would shrink.
Same random start within a seedAll arms begin from identical weights, so the only differences are what they were trained on.
A fresh head for every arm in stage 3No arm gets a head start from an old output layer. Any difference must come from the backbone, which is the part being tested.
3 seedsOne run can be lucky. Three repeats show how much results vary by chance, so a real difference can be told apart from noise.

04The model and its heads

In plain words

The network has two parts. The backbone (the "eyes") turns a photo into 512 numbers describing what it sees. A head (the "answer sheet") turns those 512 numbers into an answer such as "cat". Each task gets its own head. The backbone is shared and is where almost all the knowledge lives.

The backbone

A standard ResNet-18 adapted for 32×32 images. The first layer is a 3×3 convolution with stride 1 instead of ImageNet's 7×7 with stride 2, and the max-pool is removed, so small images are not shrunk too early. The final ImageNet layer is removed, leaving 512 features per image.

What a head is: a linear layer

In plain words

For each class, the head multiplies each of the 512 numbers by a weight, adds them up, and adds a bias. That gives the class a score, and the highest score wins. A positive weight means "this feature is evidence for this class". Training adjusts the weights until the right class scores highest.

Formally, scores = W·x + b, with W of shape 10×512 for a 10-class head. Softmax turns the scores into probabilities, and training minimizes cross-entropy. A head only makes sense for the backbone it was trained with: it has learned what each of the 512 slots means in that backbone. When stage 2 changes the backbone, slot meanings shift and the old head reads the wrong evidence. That is why the old head can fail even when the information is still present (section 6).

Why a fresh head in stage 3, for everyone

Reusing A's old head would give A an advantage the others cannot have: A's head is matched to A's backbone, and on B's or C's backbone it would be meaningless. A fresh head, seeded identically for every arm within a seed, makes the backbone the only thing that differs.

05How every stage trains

In every stage, the backbone and the active head train together (end-to-end). A new optimizer is built at the start of each stage, over the backbone and the active head only, so no momentum carries over from the previous stage and old heads stay frozen.

Reproducibility safeguards

  • Seeding: one seed fixes the starting weights, data order and augmentation. The seed is reset right before each new head is added, so every arm gets the identical new head within a seed.
  • Data workers fixed at 8: the number of loader processes changes how the augmentation randomness is drawn, so it is kept constant for the whole experiment.
  • Provenance: every checkpoint and log stores its full settings, the splits fingerprint, the device, library versions and the date. Loading refuses a checkpoint made with different splits or on a different kind of device.
  • Crash-safe resume: runs save a resume file regularly (including all random-number states), so an interrupted run continues exactly where it stopped.
  • No overwriting: saving refuses to replace an existing checkpoint, so finished results cannot be lost by accident.

The linear probe

In plain words

Freeze the network, run 5,000 CIFAR-10 photos through it, and fit the simplest possible classifier on the 512 numbers it produces. If that simple classifier does well, the network must still hold the information in an easy-to-read form. The network itself is never changed.

  1. Put the backbone in evaluation mode with no training.
  2. Extract 512 features for each of the 5,000 never-seen images (no augmentation).
  3. Standardize each feature, then fit logistic regression (scikit-learn, C = 0.1, up to 2,000 iterations).
  4. Extract features for the 10,000 CIFAR-10 test images and score the classifier. (During calibration, it was scored on validation instead.)
  5. Throw the classifier away. It is never saved into the model.

Why the probe as well as the old head: the old head can fail just because the backbone's features moved away from it. The probe fits a new reader to the features as they are, so it separates "the information is gone" from "the old reader no longer matches". Its limit: a linear reader only finds information laid out in a simple way. Information that is present but tangled can slip past it, so the probe is a lower bound.

Relearning metrics

With a constant learning rate on 5,000 images, test accuracy jumps by several points between measurements. Every metric therefore uses a smoothed curve: each point is the mean of itself and the previous two measurements. The plots show smoothed curves too.

MetricDefinitionPlain meaning
final_accMean raw test accuracy over the last 500 stepsWhere relearning ended up.
aucArea under the raw accuracy curve ÷ number of stepsAverage accuracy over the whole relearning: rewards being good early.
steps_to_50/70/80First step where the smoothed curve reaches 50/70/80%How quickly a level is reached. "Never" if not within 2,000 steps.

Gain over probefinal_acc − probe accuracy at the end of stage 2How much was added by relearning beyond what could already be read out.
Memory effectgap(A) − gap(C), where gap = result on A-seen − result on never-seenDoes A gain extra from relearning on the very photos it once trained on? B and C measure how much easier the A-seen set is by itself.

Is a difference real? For each seed we compute the difference between two arms (they share the same random start, so differences are paired). A difference is convincing when its mean is clearly larger than its spread across seeds, with the same sign in every seed. Paired t-tests are reported as a rough guide; with 3 seeds they have only 2 degrees of freedom.

07Calibration: choosing settings without peeking

In plain words

Some settings, like how hard to overwrite in stage 2, can change the result. To avoid choosing whatever makes the hypothesis look good, we did short trial runs scored on the validation photos (never the test set) and picked each setting with a rule written down before the trial. Then the setting was frozen in the config file.

All calibration used seed 1. The rules and outcomes are recorded as comments in configs/*.yaml.

7.1 · Probe regularization strength C

What C is: how strongly the probe is held back from fitting quirks of its 5,000 training images. Small C means simpler weights; large C means freer weights and more risk of overfitting. Rule: compare four values on validation (A after stage 1) and take the best that is not at the edge of the range tried.

C0.010.1110
Validation accuracy94.40%94.36%94.16%93.32%

Chosen: 0.1. It ties the best, and it is not at the edge: if the best sits at an edge, the true optimum may lie beyond it.

7.2 · Stage-2 learning rate

Why it matters: too gentle and A never looks forgotten, so the experiment tests nothing. Too harsh and everything is wiped. The first trial at 0.1 crashed A's probe from 94% to about 39% within 1,000 steps, close to an untrained network, so gentler rates were added before going further.

Rule (fixed before the 0.03 and 0.01 trials): use the gentlest rate where, after a 20-epoch trial, A's SVHN ≥ 95% and A's old head ≤ 15% (A looks forgotten), and B also reaches SVHN ≥ 95%.

7.3 · Stage-2 length

Rule (fixed before reading the 0.03 curve): the smallest whole number of SVHN epochs at which A's old head is ≤ 15%. Every real run must also end with SVHN ≥ 95%; if not, lengthen.

  1. The 0.03 curve: old head 16.4% at 500 steps, 16.8% at 1,000, 14.8% at 1,500 (epoch 2.6) → 3 epochs (1,719 steps).
  2. Seed 1 at 3 epochs: A 96.6%, C 96.5%, but B only 94.2% on SVHN, so the rule says lengthen. Those runs were archived, not used.
  3. Procedure fixed before the trial: try 4, 5, … epochs on B (seed 1) and take the first that reaches 95%. A and C only improve with more steps.
  4. B at 4 epochs (2,292 steps): 95.18% → 4 epochs for everyone. Seeds 2 and 3 use it as is; their SVHN scores are reported, not used to change it.
What this choice means. 4 epochs is one point on a dial. The calibration curves above show that at 20 epochs A's probe falls below B's. The result in this report holds for "enough overwriting that the old head looks forgotten", not for any amount of overwriting. The length was set from A's old head only; C was not separately matched (section 12).

7.4 · Stage-3 learning rate

Rule (fixed before any stage-3 run): try 0.003, 0.01, 0.03, 0.1 for A, B and C (seed 1, never-seen subset, validation, 2,000 steps). Use one rate for all arms, so they differ only in their backbone: the rate with the highest mean validation accuracy over A, B and C at the end of the budget. Two checks are reported with it: (1) if any arm's own best rate beats the shared one by more than 2 points, say so; (2) if any arm still gains more than 1 point in the last 500 steps, double the budget.

RateMean, single point at step 2,000Mean, average of steps 1,500–2,000
0.00378.74%76.65%

A change of reading, made before any real stage-3 run: single measurements jump 5–10 points, so "the end of the budget" was read as the average of the last 500 steps, not the single last point. That gives 0.003; the literal single-point reading would give 0.03. Both are reported here.

  • Check 1: A and C are best at 0.003 (the shared rate). B is best at 0.03 (70.9%) and is 4.6 points lower at 0.003 (66.3%). This favours A over B; A vs C is unaffected because both are at their best. 0.003 is also the lowest rate tried, so A's and C's true best might be lower still.
  • Check 2: gain over the last 500 steps at 0.003: A −0.1, B +0.4, C +0.6 points, all ≤ 1 → curves have levelled off, so 2,000 steps is kept.

Settings that were not calibrated

Stage 1 (lr 0.1, cosine, 200 epochs) uses the standard CIFAR recipe, long enough to converge, and is identical for A and C. The optimizer, batch size, weight decay and augmentation are standard and shared by every stage, so stages differ only in data, learning rate and length.

10What it means

In plain words

The network that seemed to have forgotten CIFAR-10 still had a lot of it hidden inside. When given a little practice, it came back better and faster than a network that had practised on similar photos, and much better than one that had not practised at all. What came back was the skill, not memory of particular pictures.

  1. "Forgotten" by the old head is not forgotten. A's old head scored 18.8%, but a fresh linear reader found 49.4%, and relearning reached 84.1%. Much of the apparent loss is the head and the backbone falling out of step.
  2. CIFAR-10-specific knowledge survives the overwrite. A beats C by 7.2 ± 0.8 points after relearning, in every seed. This cannot be explained by general photo pretraining, which C has too.
  3. Relearning reveals more than the probe. The A − C gap doubles from the probe (3.0) to relearning (7.2). Some of the surviving knowledge is not linearly readable, but training the backbone brings it back.
  4. A both starts ahead and learns faster, apart from the first ~200 steps, where C's general features help the blank head start.
  5. No sign of example memory. The surviving knowledge is general.

Scope of the claim: after an amount of overwriting that makes the old head look forgotten (4 SVHN epochs at lr 0.03), a ResNet-18 that learned CIFAR-10 relearns it from 5,000 images 7 points better than an equally trained network that learned CIFAR-100 instead.

13Open questions and next experiments

  1. How much overwriting erases it? Sweep the stage-2 length and plot the A − C relearning gap. If it falls to zero, that is where knowledge is really erased; if it levels off above zero, part survives any overwriting tried. Strongest follow-up, and it reuses the stage-1 checkpoints.
  2. Is forgetting mostly head mismatch? Relearn A starting from its old cifar10 head. A rapid jump means the features were largely intact and only the read-out was misaligned.
  3. Where is the knowledge kept? Probe each ResNet stage, or reset one stage at a time before relearning, to see which layers carry A's advantage.
  4. Does relearning return to the old weights? Weight distance and feature similarity (CKA) between the stage-1 and stage-3 checkpoints; analysis only.
  5. Fairness fixes: B at its best learning rate; a from-scratch arm; seeds 4–5.
  6. Does the advantage grow with less data? Relearn from 500 to 20,000 images.

14Glossary

Backbone
The large shared part of the network that turns an image into 512 features.
Head
A small linear layer on top of the backbone that turns features into class scores. One per task.
Arm
One version of the experiment (A, B or C), differing only in what it trained on first.
Seed
The starting number for all randomness. A different seed gives an equally valid repeat with different luck.
Epoch / step / batch
A batch is 128 images; a step is one update from one batch; an epoch is one full pass over the training set.
Learning rate
How big each update is. Larger means faster change and more disruption of what was learned.
Cosine schedule / warmup
Cosine lowers the learning rate smoothly to zero. Warmup starts it near zero and raises it over the first steps.
Momentum, weight decay
Momentum smooths updates over steps; weight decay gently pulls weights toward zero to prevent overfitting.
Augmentation
Random crops and flips of training images, so the network sees varied versions.
Validation set
Held-out images used only to choose settings.
Test set
Held-out images used only to report results.
Linear probe
A linear classifier fitted on frozen features: measures what can be read from a backbone without changing it.
Logistic regression, C
The probe's classifier. C is the inverse regularization strength: smaller C keeps weights simpler.
Calibration
Here: choosing settings with trial runs on validation data, using a rule fixed in advance.
Catastrophic forgetting
The loss of performance on an old task after training on a new one.
AUC
Here: average accuracy over the whole relearning curve.
Std, paired t-test
Std is the spread across seeds. The paired test compares two arms seed by seed.
